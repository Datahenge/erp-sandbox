| 25 | Container uid strategy | **Every service runs as the detected host uid/gid** — `--user $UID:$GID`, plus `userns_mode: keep-id` on podman only. | 28 | Supported Frappe versions | **The tool carries a table of the Frappe series it knows how to build, and refuses anything outside it.** Working out what a Frappe release needs from the machinery that installs it is human analysis of that release's own `requirements.txt`, done once per series — v12 pins `ldap3` and `PyMySQL` rather than the compiled alternatives, and predates the setuptools that removed `use_2to3`. Leaving it on fails two ways, both silently: an unguarded listener makes the child die on `EADDRINUSE` forever, and the `-m debugpy` prefix is dropped at the first reload. | 30 | Dependency conflicts between apps | **Report them; never resolve them, never fail on them.** An environment installs whatever apps its `config.toml` names, and those apps pin what they pin. erp-sandbox controls neither, so two apps disagreeing about a shared dependency is a normal consequence of that freedom rather than a defect — it resolves the way a plain `bench` would, last install wins. `build_bench.py` runs `pip check` at install time and `erp-sandbox doctor` now runs it on demand, both as a **warning**: pip mentions a conflict once, in the middle of a long log, and then exits 0, so the failure otherwise surfaces weeks later as a background job that quietly stopped. Whether a given conflict matters is a judgement about the app, and that judgement is the developer's. *(Brian, 2026-08-23: "We cannot control what Frappe Apps the user chooses to add to their TOML. Nor can we control the pinned dependencies for each. Some combination of apps may disagree on things like `rq`. It's going to happen. We allow that to resolve the same way that Frappe does… we're just obeying the Apps." This closes the open `rq` item — an app requires `rq~=1.8.1` against frappe v12's `rq==0.12.0`, and `doctor` reports a second one nobody had recorded, `redis==2.10.6` against `redis 7.0.1`.)* |

| 26 | MariaDB readiness | **`mysqladmin ping -h 127.0.0.1`**, forcing TCP and passing no credential. | 31 | Clone size | **`blobless` per app; `erp-sandbox init` writes `blobless = true` for frappe and erpnext.** The key itself still defaults to false when absent, and every app can opt out. `blobless = true` in an `[[apps]]` entry clones with `--filter=blob:none`: commits, trees and branches arrive in full, and the contents of files at old commits are fetched only when a command asks for one. Measured 2026-08-23 on `version-12`: frappe 429 MiB of objects against 47 MiB of commits and trees, erpnext 999 MiB against 59 MiB. | 38 | Nothing relies on the engine to create a bind-mount source | **Every host path `docker-compose.yml` mounts is created host-side before a container sees it.** The `conf/` files by `erp-sandbox render`, `bench/` by `erp-sandbox fetch`, and `data/mariadb` by `project.ensure_data_dirs`, called from the `infra` step and from `erp-sandbox up`. | 39 | erp-sandbox compares the frappe versions; frappe's own check is skipped | **`bench restore` is called with `--force`, and erp-sandbox reports the dump's frappe version against the bench's before restoring.** frappe's `is_downgrade()` finds the `tabInstalled Application` INSERT by scanning line by line and `eval()`s whatever follows `VALUES` **on that same line**. The check is unreachable in practice, so erp-sandbox does the comparison host-side, where the whole statement can be read, and **warns instead of aborting**. *(Brian, 2026-08-24, choosing this over passing `--force` alone: "Go with option 2, and yes, add a decisions entry.")*<br><br>**The details below are Claude's, not Brian's.** In this frappe, `restore`'s `--force` has exactly one effect — skipping that check — because `_new_site` is called with `force=True` regardless; the note in `seed_db.py` claiming `--force` caused the `DROP USER` churn was wrong, and that churn happens on every restore, which is what `prune_stale_grants` already handles. The dump is read with a streaming scan that stops at the statement (about a second on a gigabyte, gzip or plain) and tolerates both the old one-line and the new wrapped forms. Comparison uses the **numeric leading components only**, since a fork's version string carries anything after them and only the numbers order reliably; a version that yields no numbers, a dump recording no apps, and a bench not yet built each degrade to a printed line rather than an error.
